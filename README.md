# Git 提交比对

一个跑在本地的网页版 git 历史查看器：左边看提交，右边看这次提交到底改了什么，也可以勾两个提交做跨版本比对。

历史部分只读；工作区支持暂存 / 取消暂存 / 忽略，以及带文件勾选与 amend 的提交。不对公网开放。

## 位置

```
D:\tools\git-diff-viewer\
```

整个目录可直接拷贝到别处使用，无依赖、无安装步骤。

## 启动

双击 `start.bat`，或在此目录执行：

```bash
node server.js
```

启动脚本会自动找 node（PATH → `Program Files\nodejs` → 用户目录下的 node），等端口起来后打开浏览器；  
已经在跑就直接打开页面，不会起第二个实例。失败时会停在窗口里给出原因，不会一闪而过。

浏览器打开 <http://127.0.0.1:7391>，填入仓库路径（例如 `D:\code\my-project`）后点「打开」。

- 零依赖，只用 Node 内置模块 + 本机 git。
- 默认端口 7391，可用 `set PORT=8080 && node server.js` 修改。
- git 不在 PATH 时，会自动尝试常见安装位置，也可用环境变量 `GIT_BIN` 指定。
- `start.bat` / `stop.bat` 是 **GBK + CRLF** 编码，改它们时别存成 UTF-8 / LF，否则 cmd 会读错字节导致命令失效。  
  不想自动开浏览器时，先 `set GDV_NO_BROWSER=1` 再运行。

## 停止

双击 `stop.bat`：它会找出正在监听 7391 的进程并结束，确认端口释放后退出；  
服务本来就没在跑时只提示一句「服务没有在运行」。端口被别的程序占用时会给出提示并停下，不会误杀无关进程。

等价的手工做法是关掉那个最小化的 `git-diff-viewer` 窗口，或在任务管理器里结束对应 node 进程。

## 部署到 Linux 服务器（从 Windows 访问）

服务器上只要 Node（≥14）和 git，无需 `npm install`，整目录拷过去即可。

```bash
# 目录拷到服务器后
cd ~/tools/git-diff-viewer
HOST=0.0.0.0 ./start.sh start      # 后台启动，日志写 server.log
./start.sh status                  # 看是否在跑
./start.sh stop                    # 停止
HOST=0.0.0.0 ./start.sh            # 前台运行，Ctrl+C 停止
```

Windows 上直接浏览器打开：

```
http://192.168.1.202:7391/?repo=/home/yanliang/share/cursorProgect
```

- `HOST` 不设时仍只监听 `127.0.0.1`，只在服务器本机可用；`HOST=0.0.0.0` 才允许局域网访问。
- 页面里填的仓库路径是**服务器上的绝对路径**（Linux 用 `/`，例如 `/home/yanliang/share/N06`）。
- 开机自启（可选）：`crontab -e` 加一行 `@reboot cd $HOME/tools/git-diff-viewer && HOST=0.0.0.0 ./start.sh start`

**安全**：这是个无登录的服务，谁能访问这个端口，谁就能看到仓库内容、还能对仓库做暂存/提交，以及就地编辑工作区文件。只在可信内网用；  
不要映射到公网。服务器有防火墙时，只放行你自己的机器，例如  
`firewall-cmd --add-rich-rule='rule family=ipv4 source address=192.168.1.50 port port=7391 protocol=tcp accept'`。

## 能做什么

**打开仓库**

- 路径框右侧的文件夹图标可以直接**浏览服务器磁盘**选仓库：单击目录只选中，双击进入，带 `git` 徽标的目录就是仓库
- 选中并打开后就记住了，下次刷新（或重开浏览器）自动打开这个仓库
- 换仓库时地址栏的 `?repo=` 会跟着更新，所以从带参数的链接进来再选别的目录，刷新也不会跳回上一个仓库；  
  链接里找不到的仓库会自动回退到上次打开的那个
- 弹窗里的路径输入框可以直接粘完整路径回车跳转，「上一级」「主目录」用来快速移动

**看单个提交**

- 提交列表滚动加载，支持按提交信息 / 作者 / hash 搜索
- 分支、标签切换，从任意引用开始看历史
- 每个文件显示增删行数与状态（新增 / 修改 / 删除 / 重命名）
- 并排、内联两种 diff 视图，改动行做词级高亮
- 并排视图左右两栏之间的中线可以拖动，自由调整左右代码区的显示比例（双击复位，比例会记住）
- 文件筛选、单击文件头折叠、超长行自动换行、忽略空白变化

**跨版本比对**

- 勾选两个提交（列表右侧复选框），点「比对」查看两者之间的全部差异

**看未提交的改动**

- 仓库有未提交内容时，列表顶部会出现「工作区改动」，包含已暂存、未暂存和未跟踪文件
- 目录树上可按目录批量暂存、取消暂存、写入 `.git/info/exclude` 忽略；执行完原地刷新
- 选中一个被修改（M / D / R）的文件，右侧详情头部有「还原」按钮：一条 `git checkout HEAD --` 把**已暂存和未暂存的改动一起丢掉**，
  文件回到修改之前（删除的会恢复回来）。不可撤销，点了会先确认一次
- 未跟踪和新增文件没有「修改之前」可言，不提供还原入口（要丢弃请直接删文件）

**浏览仓库文件**

- 左侧栏顶部可在「改动」和「文件」之间切换：「文件」是当前版本的完整目录树，点目录展开、点文件在右侧看内容
- 从「改动」切到「文件」时会自动展开并定位到刚才选中的那个改动文件；浏览到别处后，左栏右上角的定位按钮可以跳回来
- 目录**按层加载**：展开哪个目录才读哪个，一次只取一层，仓库几万个文件也不会一次性拉过来
- 「文件」标签页的标签下方有**路径搜索**：输入即过滤出命中文件（文件名前缀命中排前面），点结果直接打开；
  `Enter` 打开第一条、`Esc` 清空。搜索走**服务端**：服务端流式读一遍该版本的文件清单建索引，
  只把命中的前 200 条回给前端，排序也在服务端做；换提交时自动收起
- 索引按「仓库 + 版本」缓存 5 分钟，同一个版本里连续搜索是毫秒级；**大仓库（如 ALPS 全量树 147 万文件）
  首次搜索要建索引，约 20 秒**，期间左栏会提示「正在建立文件索引」。服务端最多同时留两份索引
- 右侧是带行号的只读内容，可开「自动换行」；`.md` 文件同样能切成渲染预览
- 代码带语法高亮（js/ts/java/kotlin、go、c/c++、python、shell、xml/html、css、json、yaml、sql），
  行号列在横向滚动时固定在左侧；超过 4000 行会自动关掉高亮，保证滚动流畅
- 树和正文取哪个版本跟当前视图一致：提交详情看该提交、两提交比对看目标提交；
  工作区里**树按 HEAD 列目录，但正文读磁盘上的当前内容** —— 和「编辑」打开的是同一份，不会看到过期版本
- 工作区里被删掉的文件仍会出现在树上（树来自 HEAD），点开会提示「工作区已不存在」，可到「改动」里还原
- 详情顶部有「定位」按钮：一键把左栏目录树逐层展开、滚到并高亮当前文件
  （左栏正在显示搜索结果时会先退回目录树）

**源码跳转（Ctrl+Click 找定义）**

- 在「文件」视图的代码上按住 `Ctrl`（macOS 用 `Cmd`）点类名 / 方法名 / 字段名，直接跳到它的定义
- **怎么回去**：详情头最左边有「← 返回」按钮，跳过一次就亮起（左侧小圆点），点一下回到跳转前的文件和滚动位置；
  鼠标悬停会显示将回到哪个文件、还能再退几层。也可以按 `Alt+←`。返回栈最多记 50 层
- 只支持 **Java / Kotlin**：这两种语言的 import 是「包名 → 目录」的确定映射，能可靠推出文件位置
- **不建全局符号索引**：先在同文件里找定义，找不到再按 import 和同包目录用 `git ls-files` 查路径。
  所以 ALPS 那种百万文件的仓库点一下也是几十毫秒，不额外吃内存，也不用等索引
- 同名定义有多处时不猜，弹候选列表让你选；完全找不到会提示「可能来自依赖库或未跟踪的文件」
- 只能跳「定义」，不能找引用；`obj.method()` 这类链式调用给的是候选，靠你自己认

**问 AI（把代码丢给 DeepSeek Harness）**

- 代码区右上角有个「AI 问 AI」小按钮：点一下就把当前文件（或你在代码里选中的那几行）拼成一段请求，
  **复制到剪贴板**，同时打开/切入你的 DeepSeek Harness web 窗口，在那边 `Ctrl+V` 回车即可
- 第一次点会弹输入框，让你粘一条地址：终端里跑 `dsh web` 时它打印的**完整 URL（含 `?token=`）**整条粘进去。
  地址只存这台机器的浏览器 localStorage，换浏览器要重填
- 拼进去的内容有：仓库绝对路径、文件相对路径、版本（工作区 / 某个提交）、行号范围，加上选中的代码。
  没选中时：文件不超过 300 行就直接贴全文，超过只给路径让 Harness 自己去读
- **为什么是「复制 + 跳转」而不是点一下直接问**：Harness 的 web 前端只从 URL 里读 `sessionId` / `path` / `name`
  这些参数，没有预填消息的通道；要程序化建会话发消息得逆向它的私有接口，升级就废
- 浏览器不让写剪贴板时（比如用局域网 IP 访问），会弹一个已全选的文本框，`Ctrl+C` 一下一样能用
- 这个按钮只在**装了 Harness 的这台机器**上有意义：`127.0.0.1` 指向访问者自己的电脑

**纯源码模式 `?mode=source`**

- 地址后面加 `?mode=source`，界面只留「仓库路径 + 分支 + 文件树 + 代码 + 跳转」，
  提交列表、比对工具条、暂存 / 提交、编辑、AI 解释一概不显示
- 打开仓库后直接进文件视图；左栏路径搜索、定位、跳转都照常，适合当只读源码浏览器用

**就地编辑工作区文件**

- 「文件」视图 + 工作区版本时，文件头会多一个「编辑」按钮：直接在右侧改内容，`Ctrl+S` 保存、`Esc` 取消
- 滚动位置来回都能接上：源码视图滚到某处点「编辑」，光标落在同一行行首；取消或保存退出后，预览也还停在那一行
  （markdown 预览和「自动换行」模式下正文与源码行号对不上，只按滚动比例近似）
- 行号随内容实时更新，`Tab` 插入一个缩进（4 空格），多行选中时整体右移
- 有未保存的修改时，切换文件 / 切到「改动」页 / 定位到别的文件都会先确认一次，不会静默丢稿
- 保存只写已有文件（不新建、不删除），只收文本、上限 2MB；换行风格跟随原文件，
  Windows 项目里的 CRLF 不会被打成 LF（否则整个文件会在 diff 里全变红）
- 保存前会比较文件 mtime：编辑期间文件被别的编辑器或构建脚本改过，就拒绝覆盖并提示重新打开

**看文档（markdown 在线预览）**

- 选中 `.md` / `.markdown` / `.mdx` 文件时，文件头会多一个「预览」按钮，把源码正文换成排版后的文档
- 支持标题、段落、粗体/斜体/删除线、行内代码、围栏代码块、有序/无序及嵌套列表、任务列表、表格（含对齐）、引用、分隔线、链接与图片
- 图片等仓库内相对路径走 `/api/raw` 从仓库读（工作区文件或对应提交里的版本），不依赖外网；文档里的 HTML 一律转义，不会被执行
- 预览取哪个版本：提交详情里是该提交的版本，工作区里是磁盘上的最新内容，两个提交比对时取目标提交
- 再点「源码」回到逐行 diff；这个选择会记住，浏览器刷新后仍按上次的模式显示

**提交**

- 「提交…」按钮（仓库卡片上常驻，工作区视图工具条里也有）打开提交面板
- 面板列出暂存区的全部文件，可逐个勾选决定这次提交哪些（点整行即可勾选/取消）
- 下方是提交说明编辑框（第一行标题，空行后写详情），`Ctrl+Enter` 提交，`Esc` 关闭
- 勾选 `amend 上一次提交` 会自动带出上次提交说明，可只改说明、也可把新暂存的改动并进上次提交；若该提交已在远端分支，会提示需要强推
- 只提交选中的文件靠临时索引实现，未勾选的暂存内容会原样留在暂存区

**其他**

- 浅色 / 深色主题，记住上次打开的仓库
- 键盘 `j` / `k` 或上下方向键切换提交
- 点击短 hash 复制完整 hash
- 提交列表与文件树之间、文件树与 diff 之间的竖线都能拖动调宽（双击复位），宽度会记住
- 并排视图里 diff 中间那条竖线也能拖，左右两栏比例在 20%–80% 之间，双击回到 50/50

## 直接定位（可收藏）

```
http://127.0.0.1:7391/?repo=D:\code\my-project
http://127.0.0.1:7391/?repo=...&commit=abc1234
http://127.0.0.1:7391/?repo=...&cmp=abc123..def456
http://127.0.0.1:7391/?repo=...&working=1
```

可叠加 `&view=split|inline`、`&theme=light|dark`、`&wrap=1`。

## 目录

```
server.js            本地服务：只读调用 git 并输出 JSON
public/index.html    页面结构
public/style.css     界面样式（双主题）
public/app.js        diff 解析、视图渲染、交互
start.bat            Windows 启动
start.sh             Linux / macOS 启动（run | start | stop | status）
```
