## 命令速查 → 可执行 + 结果结构化展示（同日晚）

- 后端 `server-adb.js` 新增 `adb-probe`：严格白名单 `PROBES`（focus/windows/displays/policy/animator/sf-list/sf/activities/top/display/rotation），
  前端只传 `key`，不传命令行；输出截断到 512KB，返回 `{ok,cmd,serial,ms,out,truncated}`。**不要**改成接受任意命令。
- 前端 `shot.js`：点「命令速查」里可执行的行 → 弹层（`.shot-probe-mask`）→ 每个 key 一个 parser 输出 `cards / table / note / raw` 四种块。
- 真机（aiot8873p2_64_bsp / Android 14）实测格式要点，改解析前先看这些：
  - 窗口头：`Window #0 Window{hash u0 Name}:`；尺寸在 `Frames: ... frame=[l,t][r,b]`（没有 `mFrame`）
  - `displays` 里的 density 可能是 `1dpi`（副屏），要退回 `wm density` 的值
  - `policy` 字段各 ROM 差异大：mKeyguardShowing/mAwake/mScreenOnFully 常缺失，缺失时按关键字捞行
  - SF 图层头：`+ Layer (Name) uid=1000`，z 有 `-2147483648` 这种相对层级，显示成「相对」
  - `activity top` 第一条 ACTIVITY 不一定是前台，优先用布局里的 focus 覆盖；View 树是 `类名{hash 标志 bounds}` 没有 `|`
- 解析器可直接用 `node -e` 把 `function lastLine` 到 `function analyzeProbe` 这段抽出来跑，配合 `/api/adb-probe` 的真实输出验证，不用开浏览器。

## scrcpy 投屏开关（同日晚）

- 新模块 `server-scrcpy.js`：`scrcpy-status / scrcpy-start / scrcpy-stop`，只允许 loopback。
  找不到 exe 时按 `SCRCPY_BIN` → `D:\install\scrcpy-win64-v5.0.1\scrcpy-win64-v5.0.1` → PATH 顺序找。
- 拉起方式：`spawn(scrcpy.exe, args, {detached:true, stdio:'ignore', windowsHide:true})` —— 实测
  **windowsHide 只压掉控制台黑框，SDL 投屏窗口照常显示**，不需要走 scrcpy-noconsole.vbs。
- 关闭用 `taskkill /PID <pid> /T /F`，只杀自己拉起的那个 pid，用户手动开的实例不受影响（status 里 `external` 报告）。
- 前端 `shot.js` 顶栏加「投屏 / 关投屏」按钮，`paintCast()` 每次抓取后刷新状态。
- 结论：**原生窗口无法嵌进网页**，网页只能做开关 + 状态；想在页面里看画面继续用 adb 截图轮询。
