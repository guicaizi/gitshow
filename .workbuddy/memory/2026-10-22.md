## 修复 server.js 两处 git diff 相关缺陷

**背景**：git-diff-viewer 是纯本地只读工具，diff 完全由 git 原生命令算（`show -p` / `diff -p`），
同时并行取 `--numstat` 做统计，前端 `parsePatch` 手写状态机解析 unified diff 后渲染并排/内联视图，
词级高亮用 LCS 动态规划（`wordDiff`）。

**改动 1｜中文等非 ASCII 路径乱码**
- 原因：`core.quotepath` 默认 true，git 把非 ASCII 路径输出成 `"a/\344\270\255..."`，
  前端 `^diff --git a\/(.+?) b\/(.+)$` 匹配失败，文件名显示成八进制串、筛选失效。
- 修法：在 `git()` 封装里统一前置 `['-c', 'core.quotepath=false', ...args]`，一处覆盖所有调用。
- 补充：`git status --porcelain=v1` 即使关掉 quotepath，**含空格的路径仍会被引号包裹**（porcelain 格式规范），
  因此新增 `unquotePath()` 还原 C 风格转义（含 `\ooo` 八进制 → 按 UTF-8 重新解码），
  用于 `parseNumstat` 与 untracked 解析。

**改动 2｜开启"忽略空白"后统计数字与 patch 不一致**
- 原因：`--ignore-all-space` 只加到了 patch 参数，`--numstat` 分支没带。
- 修法：`readCommitDetail` / `readComparison` / `readWorkingTree` 三处 numstat 全部带上 `extra`。

**验证方式**：临时仓库覆盖 6 个提交（含 merge、纯空白改动提交）+ 中文文件名 + 含空格文件名 +
中文含空格目录 + untracked 中文文件，对所有提交在 ignoreSpace=0/1 下逐项对账
「numstat 合计 == patch 中真实 +/- 行数」，14 项全部一致；merge 提交确认 `isMerge` 为真且走 `^1` 退化分支。

**注意**：服务是长驻进程，改 server.js 后必须重启才生效。

## 文件列表改为目录树（前端）

**需求**：改动文件原本在右侧平铺成一长串完整路径，要求按项目目录树归组，点目录折叠、点文件展开对应 diff。

**实现（全部在 `public/app.js` + `public/style.css`，不涉及服务端）**
- `buildFileTree()`：按 `/` 拆路径建树，目录优先、文件在后各自排序（文件按改动量降序）。
- `compactDirs()`：**目录链压缩** —— 中间层若无文件且只有一个子目录就合并成一行
  （`src/com/android/systemui` 一行，否则 Android 这种深路径每层 14px 缩进会把文件名挤没）。
- `sumTree()`：递归聚合每个目录的 `{add, del, count}`，目录行显示 "文件数 + 胶囊 + 迷你增删条"。
- `renderTreeNode()` 递归出 `<section class="tree-dir" data-dir>` + `.dir-head` + `.dir-body`；
  文件沿用 `.file-block`，`renderFileHead(f, collapsed, depth)` 只显示 basename、靠内联 `padding-left: 16+depth*14` 缩进，`title` 保留完整路径。
- 折叠状态：`state.collapsedDirs`（Set，key 为目录 path），换提交/换仓库时与 `state.collapsed` 一起清空。
- `applyFilter()`：先算可见文件，再自底向上把祖先目录标记为可见（**注意 `closest()` 包含自身**，
  必须 `p.parentElement.closest('.tree-dir')` 往上走，否则循环第一步就退出）；有命中的目录强制展开，清空筛选后按 `collapsedDirs` 还原。

**验证**：用 Chrome headless + CDP（`--remote-debugging-port` + Runtime.evaluate）造 8 文件 Android 结构仓库实测：
目录聚合统计正确、折叠 `display:none` 生效、筛选 SystemUI 后 res 整支隐藏且祖先链完整；
浅色/深色两套主题截图确认层级缩进与配色正常。

## 未跟踪文件进树 + 工作区 git 操作（暂存 / 取消暂存 / 忽略）

**需求**：未跟踪文件也按目录树展示，文件行与目录行提供 add、忽略（写 `.git/info/exclude`）、从暂存区移除，
执行完刷新页面。

**服务端（`server.js`）**
- `parseStatusEntries()`：解析 `git status --porcelain=v1`，得到 `status: { path: {staged, dirty, untracked, xy} }`；
  重命名取 `old -> new` 的最后一段；`??` 单独标 untracked。
- status 命令改为 `-uall`：**默认 untracked 目录只输出目录名**，不展开就无法进树。
- `buildUntrackedPatch()`：未跟踪文件在 patch 里不存在，服务端读出内容合成"全是 + 行"的 unified diff
  （`--- /dev/null` / `+++ b/path` / `@@ -0,0 +1,N @@`），复用前端原有渲染链路。
  护栏：单文件 >2MB 或含 `\0` → 记成 `Binary files ... differ`；单文件 3000 行、总 400 个文件、总 8MB 预算；
  先 `stat` 再 `readFile`，避免超大文件进内存；行尾 `\r` 一律去掉。
- `git-op` 接口（**POST**，路径放 JSON 体，仍用 `execFile` 参数数组，不拼 shell）：
  `stage` → `git add -A -- <paths>`（`-A` 才能把删除也暂存）；
  `unstage` → `git reset -q HEAD -- <paths>`（无 HEAD 退化成 `git rm --cached -r`）；
  `ignore` → 追加到 `git rev-parse --git-path info/exclude`，目录写 `dir/`，重复不重复写；
  **已跟踪文件不写**（exclude 对它无效），返回提示。
- 路径校验 `safeRelPath()`：转 `/`、去前导 `/`、拒绝 `..` 与 `\0`。
- 同一路径既出现在 diff 又出现在 untracked（`git rm --cached` 后文件留在磁盘）时，跳过合成，避免树里出现两个同路径节点。

**前端（`public/app.js` / `style.css`）**
- `parsePatch` 改为**按 hunk 余量消费行**（`oldRemain`/`newRemain`），否则正文里出现 `++ ` / `-- ` 会被误判成
  `+++ `/`--- ` 文件头（合成 patch 与真实 patch 都有这个隐患）。
- `buildOpsIndex(tree)`：Map，key 为目录 path 与文件 path（**文件自身必须登记**，否则行内按钮拿不到目标，点了没反应），
  另加 `__all__` 给工具条一键全量；目录的 ignore 目标用目录本身（一条 `dir/` 覆盖以后新增文件）。
- 行内按钮：hover 时 `opacity` 0→1 显示（`:focus-within` 兼顾键盘）；
  `data-op` + `data-scope(file/dir/all)`，事件委托里先于折叠逻辑处理并 `stopPropagation`。
- 已暂存文件在行首加 `.staged-dot`（蓝色小圆点，`title="已在暂存区"`），否则"全部暂存"后看不出状态。
- `refreshWorking()`：只重取 working 详情 + repo 信息后重渲染，保留折叠/筛选/滚动位置。
- 工作区头部显示「已暂存 N / 未暂存 N / 未跟踪 N」；空树时也要 `renderToolbar()`，否则工具条残留旧按钮。

**验证**：临时仓库覆盖 `M `/` M`/`MM`/`R `/`D`/4 个未跟踪文件（含中文内容、二进制、正文以 `++`/`+++`/`---`/`@@` 开头的文件）。
- 服务端接口逐个 op 断言：stage 后变 `M `、unstage 后回 ` M`、目录批量、重复忽略、已跟踪忽略被拒、`../` 越界 400、非法 op 400。
- 浏览器 CDP 实测：8 文件块 == 工具条计数；文件/目录按钮按状态正确出现（只有未暂存的才有「暂存」，只有已暂存的才有「取消暂存」，
  只有未跟踪的才有「忽略」）；点 stage 后按钮变「取消暂存」+ 出现圆点 + 头部计数刷新；点目录忽略后整支消失；
  点按钮不会误触折叠；折叠状态在刷新后保留。浅色/深色均截图确认。

**注意**：`git reset` 掉一个已暂存的重命名后，git 会变成「暂存区删除旧名 + 新名变未跟踪」两条记录，这是 git 语义，不是 bug。


## 目录徽标数 vs 实际可见文件行对不上 —— 改为「文件 diff 默认折叠」

**现象**：用户反馈 `led 2`，展开目录只看到一个文件，"点一下第二个才显示"。

**定位**：计数逻辑没错（`sumTree` 统计 `node.files.length`，与 `renderTreeNode` 渲染同源，徽标恒等于块数）。
真正原因是**文件 diff 默认全部展开**：一个 125 行的文件把同目录第二个（空文件，`+0`）顶到 2400px 之外，
目录里"看起来只有一个文件"。用 1:1 复刻截图结构的模拟仓库（`.idea/workspace.xml` 已改 + 新增 7 文件、
`led` 下 125 行文件 + 空文件）量到两块 top 分别 2396 和 4829，证实。

**改法（只动前端 `public/app.js`）**
- `state.collapsed: Set` → `state.expanded: Set`（**默认空集 = 全部折叠**）。
  `renderFileBlock` 用 `state.expanded.has(path)` 决定 `file-body` 的 `display`。
- 工具条新增「展开全部 / 折叠全部」（`data-all="expand|collapse"` → `setAllFilesExpanded()`）；
  注意工具条已有 `[data-op]`（全部暂存）分支，新按钮必须用 `data-all` 前缀避免被那个分支吃掉。
- `applyFilter()`：筛选时目录徽标改为**命中数**，`title` 给"命中 x / 共 y 个文件"；清空筛选从
  `data-total`（渲染时写入）恢复总数 —— 之前筛选后徽标恒为总数，是"对不上"的另一处来源。
- `parsePatch` 末尾按 path 去重（同名条目合并 hunk 与统计），避免任何情况下徽标被重复项撑大。
- 空文件（hunk 存在但 `lines` 全空）展开后只显示一行 `@@ -0,0 +1,0 @@`，补 `空文件（没有内容）` 提示。

**验证（CDP 实测）**：默认 0/8 展开，`led` 两行相邻（top 495/530）；点第二个文件展开、`state.expanded` 正确；
筛选 `.bak` 后 `led` 徽标 1（title 命中 1/共 2）、只 1 块可见；清空筛选徽标恢复 2；
「展开全部」8/8、「折叠全部」0/8；目录折叠/展开仍正常；暂存操作后已展开的文件保持展开；
提交视图默认折叠且 0 个操作按钮；浅色/深色截图确认新按钮样式一致。

**注意**：前端改动不需要重启 `server.js`（静态文件每次现读），刷新页面即可。

## 20:57 新增提交面板（勾选暂存文件 + 说明编辑框 + amend）

**需求**：加一个提交按钮，弹出所有暂存区改动，可勾选其中文件，写提交说明，并支持 amend。

**服务端（server.js）**
- `git()` 增加第三参 `extraEnv`，用于注入 `GIT_INDEX_FILE`。
- 新增 `parseNameStatus()` / `readStaged(repo)`：`GET /api/staged` 返回
  `{files:[{path,status,additions,deletions,binary}], patch, hasHead, branch, short, lastMessage, headPushed}`。
  三处 diff 都带 `--no-renames`，让 name-status / numstat / patch 的路径集合一一对应
  （重命名拆成 D+A，勾选粒度才对得上）；空仓库的 branch 用 `symbolic-ref --short` 兜底。
- `opCommit(repo, message, amend, paths)`：`POST /api/commit`（与 GET 读详情同路由，按 method 分发）。
  **只提交勾选文件靠临时索引**：把 `.git/index` 复制到 `%TEMP%`，`GIT_INDEX_FILE=tmp` 下把未勾选的已暂存路径
  `git reset -q HEAD --`（无 HEAD 退化 `rm --cached`），再用 `commit -F 临时说明文件 [--amend]`。
  提交成功后对真实索引执行 `git reset -q HEAD -- <已提交路径>`，未勾选的暂存内容原样保留。
  路径必须先在真实暂存名单里，`safeRelPath` 过滤越界。返回 `{ok, short, amend, files, detail}`。
- 校验：空说明、空暂存区（非 amend）、无 HEAD 时 amend、未选文件都会返回明确中文错误。

**前端（public/app.js / index.html / style.css）**
- `state` 增加 `commitOpen/commitData/commitFiles/commitSel/commitAmend/commitMsg/commitPreview/commitBusy`。
- 抽出 `diffBodyHtml(f)`，右侧 diff 面板与提交面板预览共用。
- `openCommitPanel()` → `renderCommitPanel()`：左列暂存文件（勾选框 + 状态字母 + 目录/文件名分离显示 + 统计），
  右列预览选中文件的暂存内容，底部 amend 开关 + 说明 textarea + 取消/提交。
  目录前缀 `.stg-dir` 可省略号收缩，`.stg-base` 永不压缩。
- 细粒度同步（不整体重渲染，避免打断输入）：`syncCommitSelUI()` 同时把 `state.commitSel` 写回每个勾选框
  （这个 bug 一开始漏了：全选后单个勾选框显示不跟着变）；`syncCommitSubmit()` 管按钮可用性与「提交中…」。
- `toggleAmend()`：打开且说明为空时自动带出 `lastMessage`，关闭时若说明仍是上次原文则清空；
  已推送到远端时红线提示需要强推。amend 允许 0 文件（只改写说明）。
- 入口：`renderRepoCard()` 的 `.repo-actions` 常驻「提交…」+ 工作区工具条的 `.bulk-ops` 里「提交…」，
  统一走 document 级 `[data-open-commit]` 委托。
- 交互：`Esc` 关闭、`Ctrl/Cmd+Enter` 提交、点行切预览、点遮罩关闭；提交面板打开时 `state.commitOpen`
  会让 j/k 切换提交的快捷键直接 return。
- `afterCommit()`：重取 `/api/repo` + `loadCommits(true)`，正在看工作区时再 `refreshWorking()`。

**验证（CDP 无头 Chrome，真实 mouse click）**：3 个暂存文件全选 → 取消一个变 2/3、提示同步；全选开/关、
单文件勾选、indeterminate 正确；amend 带出上次说明、关闭清空、按钮文案切换；只勾 2 个文件提交后
`git show --stat` 只有这 2 个、未勾选的仍在暂存区、已提交文件的暂存标记消失但工作区后续改动保留；
再用 amend 把剩余文件并进上次提交，说明正确替换；空暂存区空态、浅/深色截图、Esc 关闭均正常。

**坑**：无头测试里用 `element.click()` 点 `<label>` 包着的 checkbox 会双触发（label 转发），
导致全选状态看起来"反了一格"；改用 `Input.dispatchMouseEvent` 真实点击才是真实行为，别被测试假象带偏。
