## 「文件」标签页加路径搜索

**做了什么**

- 服务端新增 `GET /api/tree-all?repo=&rev=`：`git ls-tree -r --name-only -z <rev>` 一次返回该版本全部文件路径，
  上限 `TREE_ALL_MAX = 60000`，超出部分标记 `truncated`。
- 前端「文件」标签页标签下方加搜索框（`#fileSearch`，`.file-search-wrap` + `#fileSearchClear`），输入即过滤；
  命中列表替换左栏目录树，点结果直接打开该文件；`Enter` 打开第一条、`Esc` 清空。
- 匹配排序：文件名前缀命中 > 文件名包含 > 只命中目录名；同档按目录更浅、路径更短。
  文件名命中的片段用 `<mark class="fhit">` 高亮，先转义再拼，文件名里的 `<>` 不会被当标签。
- 显示上限 200 条（`FILE_SEARCH_MAX`），超出提示「仅显示前 200 个」。

**关键决定**

- 搜索**不复用** `treeCache`：目录树是按层懒加载的，没展开的目录根本不在缓存里，
  靠已加载数据搜不到东西。所以另拉一次全量清单，按版本缓存（`state.fileSearchPaths` + `fileSearchRev`），
  同一版本里反复搜索只请求一次。
- `repaintBrowseTree()` 在搜索态直接 return，否则 `loadTreeDir` 的回调会把命中列表覆盖回目录树。
- 左栏正文统一收口到 `fileSidebarHtml()`：改动模式=目录树，文件模式=命中列表或目录树。
  `renderDiff` 与 `renderBrowserPane` 都改调它，避免两处模板各写一份（原来就是两处分别拼的，容易漏）。
- 换提交 / 换工作区时 `resetTreeState()` 一并清掉全量路径缓存，`state.fileQuery` 也清空（与 `state.filter` 一致）。
- `matchFilePaths(paths, q)` 的 `q` 需**已小写**，大小写不敏感只做在函数内部（对 path 小写化）。

**验证**

- 接口实测：`n06liquidglass` 的 HEAD 返回 15 条，路径与实际仓库一致。
- 前端逻辑测试：从 `app.js` 里抽出 `matchFilePaths / hlMatch / fileSearchHtml` 用 `new Function` 沙箱跑 18 项断言全过
  （排序、大小写、中文空格路径、无匹配、高亮转义、200 条截断、加载中/出错文案）。
- **踩坑**：测试里用 `eval` 加载这些函数会报 `Identifier 'matchFilePaths' has already been declared` ——
  直接 `eval` 的函数声明会落到外层模块作用域，和外层 `const matchFilePaths` 解构撞名。用 `new Function(code)()` 才干净。

**已知边界**：搜索基于 `browseRev()` 的清单，工作区模式下是 HEAD，所以**未跟踪的新文件搜不到**（和目录树表现一致）。

## 「文件」搜索改成服务端（12:05）

**起因**：用户截图报 `读取文件列表失败：stdout maxBuffer length exceeded`。
排查发现他打开的是 **`Z:\N06\u0.mp1.rc-aiot_alps`（MTK ALPS 全量树）**：`git ls-tree -r -z` 有
**147 万条路径 / 126MB**，超了 `MAX_BUFFER`（64MB）——调大上限也没用，126MB 的 JSON 也塞不进浏览器。

**做法**：`/api/tree-all` 删掉，改 `/api/tree-search`：
- `spawn` + `stdout.setEncoding('utf8')` 流式拼一个大字符串（**不用 execFile，彻底绕开 maxBuffer**；
  setEncoding 走 StringDecoder，中文路径跨块不裂），`\0` 保留作分隔符，**不 replace 成 `\n`**（省一次 126MB 拷贝）。
- 索引按 `repo\nrev` 缓存，TTL 5 分钟，最多 2 份 / 总字符 300MB 双闸淘汰。
- 搜索在服务端用 `new RegExp(q,'i')` 扫大字符串（不做小写副本），命中后 `lastIndex = 路径结尾+1`
  保证一条路径只算一次；候选数组到 4000 条就排序截到 1000（打一个字母命中 143 万时不炸）。
- 前端改成防抖 220ms + 轮询：服务端返回 `{state:'building'}` 就每 800ms 再问一次，建好再渲染命中。

**实测**：ALPS 首次建索引 **22.7s**（SMB 上读 .git），之后同版本查询 108ms；`window` 命中 7987、
`WindowManager` 1980 且排序与旧的本地过滤**完全一致**（实测 6 条样例顺序逐条对上）；单字母查询 913ms。
索引常驻内存约 **430MB**（147万路径字符串）。中文查询用**百分号编码**传才准，bash 里直接塞原文 curl 会乱码（不是代码问题）。

**服务端同步**：server.js / app.js / README 已传 192.168.1.202 并重启；旧 `/api/tree-all` 已下线（返回「未知接口」）。

## 文件详情顶部「定位」（2026-10-26 11:58）

**做了什么**：详情头路径右侧加两个按钮 —— ①「定位」（十字准星）复用 `revealInTree` 逐层展开左栏目录树 →
`repaintBrowseTree` → `scrollToBrowseSel(true)`（`block:center` + 1.4s 描边闪烁）；②「↗」复用已有
`revealPath`，走 `/api/reveal` 在系统文件管理器里选中该文件（仅本机可用，局域网访问会提示）。

**踩到的点**：左栏处于搜索命中列表时目录树被整个替换掉，定位前必须 `clearFileSearch(false)` 退回树；
`revealInTree` 逐层 `loadTreeDir(..., true)` 是静默的，所以**失败时也要 repaint 一次**，否则左栏停在「读取目录…」。
