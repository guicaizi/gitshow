## 09:10 修竖向分隔线拖不动（命中区被遮挡）

**反馈**：用户指着「文件树 / diff」之间的竖线说「中间分割线可以拖动」——实际代码里早就实现了拖拽（`#paneResizer`），
但他拖不动。

**根因**：`.resizer` 和 `.pane-resizer` 只写了 `z-index: 5/6`，**没有 `position`**，z-index 对 static 元素无效；
这两个 4px 的条用 `margin-left: -2px` 骑在两个面板交界处，后半 2px 被后面的兄弟节点（`.detail` / `.diff-pane`）
的背景盖掉，实际只有约 2px 可点，鼠标基本抓不住。

**改动**
- `style.css`：两条分割线合并成一套规则 —— `position: relative; z-index: 6` + `::before` 左右各外扩 4px 形成 12px
  命中区（视觉仍是细线）+ `::after` 2px 强调线，hover/dragging 变 `var(--accent)`；新增 `body.col-resizing`
  （`cursor: col-resize` + `user-select: none`），删掉原来 hover 的 `--accent-soft` 底色规则。
- `app.js`：两条拖拽都改成用 `body.col-resizing` 控制光标（原来直接写 `body.style.cursor`，不统一）；
  新增 dblclick 复位（文件栏回 268px、提交栏回 344px，并清 localStorage 的 `gdv.filepane` / `gdv.sidebar`）；
  `title` 改为「拖动调整…宽度，双击复位」。
- `README.md` 其他一节补一句说明。

**验证**（CDP 无头 Chrome，1440×900）
- 关键回归：从分割线**右侧 3px**（原来被 diff 栏盖住的位置）起拖，文件栏 268 → 353，成立。
- 侧栏同样从右侧 3px 起拖，344 → 409。
- 双击复位：文件栏回 268 且 `localStorage.gdv.filepane` 被清空。
- hover 时 `::after` 背景 = `rgb(9,105,218)`（accent）；`.pane-resizer` 计算宽度 4px、`::before` 12px。
- 拖动中 `#paneResizer` 带 `dragging`、body 带 `col-resizing`、`user-select: none`；松开后 body 类清空。
- 已在服务器实例 `http://192.168.1.202:7391` 上复测同样四项，结果一致（前端文件已 scp 同步，静态文件无需重启）。

**注意**：以后给这类"绝对定位感"的分割条加 `z-index` 必须同时给 `position`，否则被后续兄弟节点盖住半边。

## 11:35 并排 diff 中间加可拖动中线，自由调左右比例

**需求**：代码差异区域（并排视图）中间也加一根线，可拖动调整左右显示比例。

**做法**
- `style.css`：`.drow` 的 grid 从写死 `46px 1fr 46px 1fr` 改成
  `46px minmax(0, var(--split-l, 1fr)) 46px minmax(0, var(--split-r, 1fr))`，比例靠 :root 上的两个 fr 变量控制；
  `.diff-pane` 补 `position: relative`；新增 `.split-handle`（11px 命中区、1px 淡线 `--border`、hover/拖动态变 2px `--accent` + soft 光晕）。
- `app.js`：`state.splitRatio`（localStorage `gdv.splitRatio`，默认 0.5，夹紧 0.2~0.8）；
  `applySplitRatio()` 换算成 fr（0.5→1fr:1fr）；`updateSplitHandle()` 把中线贴到左右代码列真实分界处
  （`left = 第一行左 code 的 right - pane.left`，`top = diff-pane-head.offsetHeight`）；
  renderSelectedFile 里 `pane.classList.toggle('split-mode', state.view === 'split')` 并追加 `<div id="splitHandle">`；
  拖动用 `#diffScroll` 上的 mousedown 委托 + document mousemove/up，双击复位 50/50 并清 localStorage。

**关键设计决定**
- handle **不能放进 `#diffPaneBody`**（那是滚动容器，绝对定位会随内容滚走），必须挂在 `.diff-pane` 下、按 head 高度下移。
- 位置不按比例算，而是**实测第一行 `.code.wrap-gutter` 的右边界**——这样垂直滚动条、内联切换、wrap 换行都不会错位。
- 更新时机：`renderSelectedFile` 之后、`window.resize`、文件栏 resizer 与提交栏 resizer 拖动中。
- 内联视图下 `updateSplitHandle()` 直接隐藏（单栏没有比例概念）。

**验证**（CDP 无头 Chrome，真实 mouse 事件，本地 + 192.168.1.202 各跑一遍）
- 初始中线绝对位置 == 左 code 右边界（1020 vs 1020），行号列恒 46px；
- 右拖 +120：358/358 → 478/238，实测 478/238=2.008 与 1.335fr/0.665fr 换算一致；
- 拖到极限夹紧在 0.2/0.8（143/573）；双击复位 1fr:1fr 且 `gdv.splitRatio` 被删；
- 切内联 handle `display:none`、code 恢复整宽 762；切回并排恢复；
- 拖动后 ratio 0.584，刷新后仍是 418/298；
- 深色主题 hover 线 `rgb(68,147,248)` 2px，拖动中 `body.col-resizing` + handle `.dragging`；服务器 355 行文件同样正常。

**取舍**：中间 11px 命中区会挡住该处的文本选择（VS Code 同样处理）；只对并排视图生效。
