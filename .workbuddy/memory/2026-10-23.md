## 17:45 修 Windows 下双击 start.bat 无法启动

**现象**：双击 `start.bat` 一闪而过，服务没起来，页面打不开。

**根因（两层）**
1. **主因：bat 是 LF 换行**（只有 `\n` 没有 `\r`）。cmd 靠 `\r\n` 定位行边界，LF-only 会让每行开头字节被吃掉：
   实测 `'et' 不是内部或外部命令`（set 丢 s）、`'ode' …`（node 丢 n）、`'in' …`，整个脚本全线失效。
2. **次因：`chcp 65001` + UTF-8 中文长行**。在 65001 下 cmd 按字符数算行偏移，多字节中文让后续行错位，
   `echo 请还原最小化的 "git-diff-viewer" …` 直接变成 `'o' is not recognized`（前面短句反而正常）。

**最终做法**
- `start.bat` 改为 **GBK 编码 + CRLF + `chcp 936`**。cmd 原生 ANSI 代码页是 DBCS，没有 65001 的字节错位问题；
  `chcp 936` 保证从 65001 的终端里跑也能正常显示中文。
- 脚本增强：
  - node 查找 `where node` → `%ProgramFiles%\nodejs` → `%LOCALAPPDATA%\Programs\nodejs` → 本机托管 node；
    找不到时中文提示 + `pause`，不再闪退。
  - 端口占用检测（`netstat|findstr ":7391 "|findstr LISTENING` 封成 `:is_up` 子程序）：已在跑就直接开浏览器，
    不启第二个实例；启动后轮询 8 次（每次约 1s）起来才开浏览器。
  - 启动失败（8 秒端口没起来）给中文原因 + `pause`，提示还原最小化窗口看报错。
  - `GDV_NO_BROWSER=1` 跳过自动开浏览器（测试/服务器用）。
- **等待不能用 `timeout /t`**：PATH 含 Git 的 usr/bin 时会被 coreutils 的 `timeout` 抢走（报 `invalid time interval '/t'`），
  改用 `ping -n N 127.0.0.1 >nul`。
- README 启动节补编码警告与 `GDV_NO_BROWSER` 说明。

**验证**（cmd 真实执行，PATH 剔除 PortableGit/usr/bin 模拟双击；输出重定向后用 iconv 按 GBK 解码核对）
- 端口空闲：正常启动、`/api/ping` 200、首页 200，中文三行正常；
- 端口已占：输出「服务已经在运行，直接打开页面」，监听数仍为 1（没起第二个 node）；
- 移走 server.js 制造失败：完整输出三行中文错误 + pause，无 `'o' is not recognized`，server.js 已还原。

**坑**：从 Git Bash 用管道接 cmd 输出会卡死（`start` 派生的 node 继承 stdout 句柄，管道等不到 EOF），
测试要改成 `> 文件 2>&1 < /dev/null`；`cmd //c start "" cmd /c "x.bat"` 这种嵌套会被安全策略拦。

## 17:52 新增 stop.bat（按端口停止服务）

## 21:05 仓库文件树浏览（左栏「改动 / 文件」+ 按层懒加载）

**需求**：想能在工具里浏览整个仓库的文件（结构树），担心仓库大、性能吃不住。

**性能结论（实测，回答用户的核心疑问）**
- 造 2 万文件仓库：`git ls-tree -r -l HEAD`（全量）**0.09s**，`git ls-tree -l HEAD`（根目录单层）**<0.01s**，
  单层 HTTP 端到端 **~10ms / 3~4KB**。
- 所以 git 本身不是瓶颈；真正会卡的是**把全量清单传给浏览器再画成 DOM**（2 万行的 JSON ~3MB + 2 万个节点）。
  用按层加载后，代价只和「展开的那一层有多少项」有关，与仓库总大小无关。
- 顺带记：`ls-tree` 单层用 `git ls-tree -l <rev> -- <dir>/`，不带 `-r`；trailing 斜杠避免匹配到同名文件。

**服务端（server.js）**
- `readTree(repo, rev, path)`：`safeRev` 兜底 HEAD，路径去前导斜杠 + 禁 `..`/`\0` + 补尾斜杠；
  解析 `mode type object size\tpath`，`type==='tree'` 进 dirs，其余进 files（带 size/mode）；目录与文件分别按 `localeCompare('zh-CN',{numeric:true})` 排。
- 路由 `GET /api/tree` → `{rev, path, dirs[], files[]}`，放在 `/api/file` 前。

**前端（public/app.js）**
- `state.browse`（localStorage `gdv.browse`）、`browseSel`、`treeCache`（Map dir→data）、`treeOpen`（Set）、`treeLoading`、`browseToken`。
- 左栏头部换成 `.pane-tabs`：「改动 N」/「文件」；文件模式下**隐藏筛选框**（懒加载树没法本地过滤）。
- `renderBrowserPane()` 切换两种左栏；`renderRightPane()` 分发到 `renderSelectedFile()` 或 `renderBrowseFile()`。
- `loadTreeDir()` 只取一层，展开时才请求；渲染用 `renderBrowseNodes()` **整棵已加载树重建**（节点少，比增量插入可靠），
  重建前后保存/恢复 `.file-tree` 的 scrollTop。
- `renderBrowseFile()`：头部显示路径 + `大小 · 行数`，正文 `renderCodeView()`（行号列宽度 `--fv-w` 按总行数算，>6000 行截断提示）；
  `.md` 复用 `#mdToggle` 与 `markdownToHtml`，切预览时工具条显示「Markdown 预览」。
- `resetTreeState()` 在 `renderDiff` 里按 `browseRev()` 变化触发（换提交才清缓存，工作区刷新保留展开状态）。
- 改动为空的提交不再直接返回 skeleton，只要 browse==='files' 仍渲染双栏，保证能切到文件树。

**验证（CDP 真实点击，本地 Windows）**：tabs 显示「改动3/文件」；切文件后筛选框消失、根目录 2 目录 + 5 文件；
展开 public 出 3 个文件；打开 `public/app.js` 2639 行 / 98KB / 行号正确；README.md 有预览按钮且能渲染；
切回改动恢复 3 个文件树 + 340 行 diff + 并排/内联按钮。服务器 md5 已同步并重启，`/api/tree` 返回正常。

**未加的保护**（已知，需要时再补）：单目录项数没有上限（极端情况某目录几万文件仍会全量下发），
文件树不支持筛选/搜索，文件内容没有语法高亮。

## 21:25 改动文件 → 文件树联动定位

**需求**：在「改动」里选中的文件，切到「文件」时能直接定位过去；也可以给个按钮手动定位。

**做法（public/app.js + style.css，未动 server.js）**
- `revealInTree(path, silent)`：按 `path.split('/')` 逐层查 `treeCache`，缺哪层就 `loadTreeDir` 补哪层，
  每层把目录写进 `treeOpen` 展开，最后 `state.browseSel = path`。任一层的 dir/file 不存在就返回 false
  （silent 时静默，手动点按钮时 toast「「改动」里选中的文件不在当前版本中」）。
- `switchBrowse('files')` 后若 `state.selected` 存在，自动 `revealInTree(..., true)` → `repaintBrowseTree()` →
  `scrollToBrowseSel()`（`scrollIntoView({block:'nearest'})`）→ `renderBrowseFile()`。
- 左栏 pane-head 右侧加 `.pane-icon-btn#revealChange`（准星 SVG，仅文件模式且 `state.selected` 有值时渲染），
  点击走同一套 reveal，失败带提示。
- `repaintBrowseTree()` 抽出「整棵已加载树重绘 + 保留 scrollTop」，`loadTreeDir` 与各调用点共用。

**修掉的竞态（重要）**：切 tab 时 `renderBrowserPane()` 和 `revealInTree()` 会同时请求根目录，
原来 `loadTreeDir` 用 `treeLoading.has(dir) → return` 直接放弃第二次调用，导致 reveal 拿不到 cache 直接失败
（表现：切过去没定位）。改成 `state.treeLoading` 由 `Set` 变 `Map<dir, Promise>`，**同一目录并发共享同一个 Promise**，
两个调用者都 await 到完成。

`.workbuddy` + `.workbuddy/memory`、选中该文件、右侧 221 行；点别的文件后点定位按钮跳回；根目录文件（server.js）
定位正确（1078 行）。服务器 app.js/style.css 已同步（md5 一致），server.js 未改故无需重启。

## 21:50 文件浏览的代码语法高亮（零依赖）

**先走偏了一次**：把「.html 美化」理解成给 html 做渲染预览，写了 `/api/site/<b64repo>/<rev>/<path>` 的静态资源通道
（MIME 扩展 + serveRepoSite + repo 校验缓存），用户明确说"方向错了，我就是纯看代码好看点"。
**已全部回退**（server.js 清理干净，`node -c` 通过；前端 html 预览没写所以无需回退）。

**最终做的：语法高亮（public/app.js + style.css，server.js 未改）**
- `HL_LANG` 扩展名 → 语言（js/ts/java+kotlin+gradle/go/c-family/py/sh/xml+css/json/sql/yaml）；
  `HL_KW` 每语言关键字表（首次用 `Set` 缓存）；`HL_SYN` 配行注释/块注释/引号/多行引号。
- `hlLine(line, syn, kw, st)` 逐行状态机，`st.blockEnd/blockCls` 跨行传递 → `/* */`、模板字符串能正确着色且行数不乱。
- token 分类：`k` 关键字 / `s` 字符串 / `c` 注释 / `n` 数字 / `f` 函数调用（标识符后紧跟 `(`）/ `t` 大驼峰类型 / `a` @注解。
- 配色走 CSS 变量 `--tk-k/s/c/n/f/t/a`，浅色对齐 GitHub（#cf222e/#0a3069/#6e7781/#0550ae/#8250df/#953800），
  深色对应 #ff7b72/#a5d6ff/#8b949e/#79c0ff/#d2a8ff/#ffa657。

**两个真 bug（都调试出来了）**
1. **词法死循环**：`/[A-Za-z_$@]/` 命中 `@` 时，`while(/[\w$]/)` 不前进 → `j===i` → `i` 不递增 → 无限循环，
   表现是打开 `app.js` 整个页面卡死、CDP 命令全部无响应（第一次以为是 DOM 太重）。改成 `let j = i + 1` 起步。
2. **class 拼错**：`class="tk ${cls}"` 生成 `tk k`，而 CSS 写的是 `.tk-k`，结果有 span 但没颜色（`spans` 有值、各类别全 0）。
   改成 `tk tk-${cls}`。

**渲染结构重构**：原来「每行一个 `.fv-row` div + 行号 span + 代码 span」，2639 行 ≈ 2 万节点；
改成**两个 `<pre>`**（`.fv-gutter` 行号纯文本 + `.fv-code` 代码），节点数少一个量级，
app.js 2639 行高亮后 3948 个 span，渲染 **249~338ms**。行号 `position: sticky; left: 0`，横向滚动时固定。
`HL_MAX_LINES = 4000`（超过则不高亮并在底部提示），显示上限仍是 6000 行。

**验证**：app.js 2639 行 k=1239/s=1264/c=216/n=217/f=850/t=154/a=8；style.css 1929 行（数字 1006 个，全是 px 值）；
server.js 1078 行；浅/深两套截图确认配色正常；横向滚动 124px 后行号仍贴在左边（gutterLeft=0）。
