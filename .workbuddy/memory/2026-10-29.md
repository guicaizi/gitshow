## 坑

- Git Bash 会把 `D:\tmp\x` 参数转成 `D:/tmp/x`（传给 node/curl 时），测试要用文件或 `MSYS_NO_PATHCONV=1`，
  否则写进配对的路径会变成 `D://tmp//...`。已在 `writePairs` 里用 `path.resolve` 兜底归一化。
- 无头 Chrome 截图脚本：`Page.captureScreenshot` + `Emulation.setDeviceMetricsOverride`，
  面板类 UI 用它验证比人工点更快；用完记得关 chrome 并删 profile。
- 真机验证不能拿 /system/framework 试，改用 `/data/local/tmp/<dir>` 作为 remote，全链路可测且无风险。

## 组合包（20:16 之后追加）

- 需求：勾选的配对能自由组合成「组合包」，取名、永久保存、可删、可整包执行。
- 存储：`.gdv/adb-packs.json`，存的是配对**快照**（local/remote），不引用配对 id——
  删掉配对不会弄坏包；载入时找不到的配对会顺手补回配对列表。
- 接口：`GET /api/adb-packs`、`POST /api/adb-packs-save`（整表覆盖）、
  `POST /api/adb-check`（传一组 pairing，回两端是否还存在，供执行前预检）。
- 执行复用 `adb-replace`：`startReplace(only, label)` 第一参传数组就按这组跑，
  不传才走「按勾选执行」；组合包执行会先 adb-check 过滤掉本地已不存在的文件。
- 「载入」语义 = 把这包的配对设为**唯一选中**（其余取消），再点「执行选中配对」即可微调后跑。
- 顺手修：`safeRemote` / `readPairs` 把重复的 `//` 收成 `/`（历史数据里出现过 `//system/framework/...`）。
- 验证：真机 aiot8873p2_64_bsp 往 `/data/local/tmp/packtest` 跑通（1/1 成功），测完已清目录与包。
  ⚠️ 那次测试勾着「完成后重启设备」，真机被重启了一次。
