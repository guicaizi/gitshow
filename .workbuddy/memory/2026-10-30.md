## ADB 面板：非 root 徽标改为可点的提权按钮

- 需求：设备非 root 时点徽标，先跑 `adb root` + `adb remount`，再给出真实 root 状态。
- 接口：`POST /api/adb-root`（`server-adb.js` 的 `elevate()`）。不抛异常，每步原始输出塞进 `steps` 返回。
- 幂等设计：先 `id -u` 判断，**已经是 root 就不跑 `adb root`**——它会让 adbd 重启、设备短暂 offline，
  能省一次断连。实测第二次调用只走 3 步（id / remount / 探针）。
- 顺序：`adb root` → `wait-for-device`（必须，adbd 重启后设备掉线）→ `id -u` 复核 →
  `adb remount` → 失败退回 `mount -o rw,remount /` → 再 `wait-for-device`（Android 10+ overlayfs 的 remount 会重启 adbd）→ 写探针。
- 用 `touch /system/.gdv_probe` 探针判断可写，**比看 remount 输出可靠**（输出有 Remounted 但实际只读的情况存在）。
- user 版本早退：`cannot run as root` 时直接返回 `production: true` + 明确提示，不继续无效操作。
- 前端：`非 root · 点此提权` → 点击后 `提权中…` 置灰 → 成功后 `root 已获取 · /system 可写`（绿）；
  remount 失败则是 `root 已获取 · 未 remount`，失败原因常驻设备行下方（`.adb-root-err`），不只靠 toast。
- `S.rootInfo` 只在内存里，刷新页面后只剩「root 已获取」——root 身份是真的，remount 细节需要重新点一次才显示。
- 实测真机 aiot8873p2_64_bsp（Android 14 / userdebug）：点按钮 2 秒完成，uid 0、Remounted /system as RW、探针 OK。
  测完设备保持 root + /system 可写状态（重启恢复）。
