## 根提交（一次性导入上万个文件）详情显示「没有文件改动」的修复

- 仓库：`D:\yanliangwork\myprogect\Setting_project\MtkSettings`，`git rev-list --count HEAD` = 1，
  唯一提交一次导入 7027 个文件；`git show` 的整份 patch 有 **114 MB**。
- 原因：`server.js` 的 `git()` 封装 `maxBuffer = 64MB`，读 patch 抛
  `stdout maxBuffer length exceeded`，原来被 `.catch` 成一段错误字符串塞进 `patch`；
  前端 `renderDiff()` 只从 `parsePatch(d.patch)` 取文件列表 → 补丁为空 → 误报「这次提交没有文件改动」，
  连 7027 个文件的清单也一起消失了。
- 改法（服务端）：`readCommitDetail` 把 patch 失败结构化返回 `patchError: 'too-large' | 'failed'`
  + `patchErrorDetail`，`files`（numstat）照常返回；
  新增 `readFileDiff()` 与 `GET /api/file-diff?repo&hash&path&ignoreSpace`，
  根提交用 `git show <hash> --format= -- <path>`，普通提交用 `git diff <parent> <hash> -- <path>`。
- 改法（前端）：`lazyFilesFromNumstat()` 用 numstat 清单构造文件条目（`lazy: true`）；
  `renderSelectedFile()` 遇到 lazy 条目先显示「正在读取这个文件的改动…」并调 `ensureFilePatch()`，
  拿到单文件补丁后只重绘这一个文件；工具栏加「补丁过大 · 按文件加载」标签，打开时 toast 提示一次。
- 验证：无头 Edge（CDP 9223）打开 `?repo=...&commit=95d19cc` → 标题 `MtkSettings · Git 提交比对`、
  计数 7027 个文件 +1352859、首文件自动按需加载出 `@@ -0,0 +1,275 @@`；普通提交（本仓库 b8ae90a）12 个文件正常。
- 坑：本地实例杀进程后用 `Start-Process` / WMI `Win32_Process.Create` 拉起来都会被会话清理杀回；
  PowerShell 工具不允许 `cmd /c`。最后用 Bash `run_in_background` 起（会话内有效），
  用户长期使用仍靠双击 `start.bat`。
